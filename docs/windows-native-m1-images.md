# Windows 迁移：截图缓存与阅读器补齐

日期：2026-11-01。对应 W10 的本机实现与验证；Windows 平台验收继续延后。

## 实现

`SlideImageCache` 只根据固定账号的当前课次/截图索引查找资源，网页不能提交下载 URL 或文件路径。下载域与旧导出器一致，仅允许 `https://resource.msa.buaa.edu.cn`，拒绝自定义端口、用户信息、查询串、片段、重定向和非 200 响应；不携带学校 Cookie、token、模型 Key 或默认鉴权头。实际接收流限 12 MiB，不仅检查 Content-Length。等待和下载共同受 30 秒操作期限约束。

Rust 新增原图检查 C ABI，支持 PNG/JPEG/WebP，先检查大小/尺寸和解码输出量，再完成真实解码；拒绝损坏内容、其他格式、超过 2000 万像素或单图 12 MiB 的输入。缓存保存原始字节及其 SHA-256，不缩放、不做有损重新编码。`image` 0.25.10 仅启用三个 codec，并锁定在 Cargo.lock。

解码器另外设置 256 MiB 分配限制，但这是库层的 best-effort 限制，不是进程内存硬上限；像素数与解码输出量由本项目明确检查。PDF 批次的累计下载/解码预算仍在 W16 实施，不能将单图检查算作 PDF 已完成。接口依据：[ImageReader](https://docs.rs/image/0.25.10/image/struct.ImageReader.html)、[Limits](https://docs.rs/image/0.25.10/image/struct.Limits.html)。

缓存原图放在私有缓存目录的账号哈希子目录，文件名仅由资源地址哈希和内容哈希构成。元数据通过同一 Rust SQLite 的 owner-scoped `meta` 保存，没有另建业务数据库或改变 schema。原图校验后先写临时文件，移动后最后提交元数据；缓存文件与 SQLite 不共用事务，异常可能留下未引用的文件，但不会把未验证内容登记为有效缓存。原图校验失败或缓存缺失时可重新获取，已有笔记/evidence 不受影响。

缓存命中只读本地，不请求网络。图片读取不占住业务消息桥；切账号/退出会撤销旧账号的图片操作令牌，旧结果保持原账号标签。关闭时先取消并等待图片操作退出，再释放工作区；停止超时不伪装成已安全关闭。

## 页面

- 按截图索引逐张浏览，显示原始分辨率图片；只保留当前张的展示数据。未缓存和损坏状态均提供获取/重试入口，不承诺自动离线保存全部图片。
- 标签进入后立即保存；截图位置按图片 ID 记录，刷新可恢复。材料/分析快照变化会重新建立阅读视图，避免原文继续显示旧片段。
- 材料页显示文本时间覆盖率、长空白区间与识别限制，不将覆盖率称为准确率。
- 笔记来源可在引用范围与完整的旧 evidence 快照之间切换；完整快照按 100 段分页，不静默切到刷新的材料。
- 顶部与对应课次阅读器显示同一个持久化活动任务；无虚构百分比。
