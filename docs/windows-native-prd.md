## 1. 目标与交付边界

让北航学生在 Windows 上安装后即可连接学校、同步课程、阅读课堂材料、生成带来源的时间轴笔记、问答、管理作业、导出及自动获取新材料。

- 确认交付形态：C# / WinUI 3 窗口承载本地 React 业务界面，Rust 共享业务内核；业务 WebView2 与学校登录/录播授权 WebView2 独立隔离。无 Python/Node 运行时和本地 HTTP 服务。该路线为 Windows 平台宿主与共享内核迁移，不再宣称全部业务界面原生。
- 用户无需安装 Python、Node.js 或开发工具；不依赖本地 HTTP 服务及固定端口。
- 保留现有页面的信息结构与暖白视觉风格，适配 Windows 窗口和控件交互。
- 首发验收平台为 Windows 11 x64；ARM64 和 Windows 10 不进入首发兼容承诺。
- 现有 Electron Windows 版本在原生版完成全部发布门槛前继续提供。

首版不增加 OCR、截图视觉分析、音频转写、向量检索、云端同步、多用户服务、课程视频下载、自动提交作业、系统后台服务或消息推送。应用退出后不执行自动化。

## 2. 用户路径与页面

首次使用：安装 → 打开 → 连接北航 → 完成学校认证 → 获取学期、课程和课表 → 进入课程 → 同步课次 → 获取材料 → 阅读原文或配置模型并分析。

后续使用：打开上次本地账号的课程列表 → 进入课程继续阅读 → 需要更新学校材料时重新登录。仅模型调用不应无故要求学校在线，但必须已有该账号的可用课堂文本。

Windows 版不迁移“开始学习”首页、首页问题输入和快捷提问建议。默认入口为“本学期课程”，无本地课程时在该页显示连接学校入口；课程问答仅在进入课程后提供。

页面结构：

| 页面 | 内容和主要操作 |
| --- | --- |
| 本学期课程 | 学期选择、课程列表、回放数量、同步状态、真实课表、同步入口 |
| 课程学习 | 课次列表、材料/分析状态；打开时间轴、原文、截图、材料情况、原始回放、导出；切换课程问答 |
| 课堂阅读器 | 时间轴 / 原始识别文本 / PPT 截图 / 材料情况；来源定位、搜索和继续阅读 |
| 作业与事项 | 作业完成勾选、截止与提交信息、待核验状态、重要事项及课堂来源 |
| 课程自动化 | 多课程搜索与筛选、自动获取、自动笔记、批量操作、统一保存 |
| 任务状态 | 当前及历史任务、进度、失败原因、重试、结果入口 |
| 模型与设置 | 服务地址、模型名称、密钥管理、本地数据位置、旧版数据导入 |

仅设置一个位于顶栏左侧的侧栏触发器。短操作用状态或按钮表达，不增加重复副标题与功能说明。材料缺失、错误、模型费用及登录条件提示必须保留。

### 3.1 与现状有意不同的行为

- **移除“开始学习”首页。** 启动默认进入本学期课程，不提供首页课程选择、问题输入、发送及建议问题入口；课程内问答继续保留。
- **课次学习页只以时间轴组织笔记。** 当前 `lessonOverview()` 仍有独立作业、事项和复习建议列；Windows 不照搬这些重复区块。提取数据与全局“作业与事项”继续保留，时间轴内可呈现该段相关事实。
- **离线记录可直接阅读。** 不照搬旧 API 中部分读取操作受学校登录状态限制的实现。
- **API Key 进入系统凭据管理器。** 旧网页界面设置的 Key 只留在进程，Windows 版增加安全持久化、移除和失效提示。
- **学校返回多学期时由用户明确选择。** 不假定第一项一定是当前学期。
- Markdown 可保留现有完整信息字段；“仅时间轴”限制针对学习笔记界面，不以简化 UI 为理由丢弃导出或迁移数据。

## 4. 关键行为与异常要求

### 4.1 登录、账号与网络

- 连接状态：未连接 → 登录中 → 学校已连接/录播待授权 → 已连接；取消、失败和过期明确显示，不以打开页面等同登录成功。
- 只有实际读取目标课程录播目录成功才确认其录播授权有效；教学空间凭据与录播凭据不能跨域转发。
- WebView2 使用独立临时资料目录；禁止读取系统 Edge 资料，登录页面不获得本机文件/数据库调用桥。结束后释放进程和清理目录，异常退出遗留目录下次启动清理。
- 密码只在学校页面输入；学校 Cookie/token 不写 SQLite、配置、日志、诊断包。模型密钥只写系统凭据管理器。
- 学校 HTTP 使用精确主机限制、TLS 校验、超时、响应大小限制和禁止自动重定向；登录浏览器允许的跳转链独立维护。
- 若学校拒绝嵌入式登录，M0 判定阻塞，先验证学校实际支持的替代方式；不假设存在 OAuth/MSAL 回调。
- 切账号时停止旧账号调度，等待活动调用安全退出后切换上下文；返回的旧任务结果只能写入原账号，不能刷新新账号页面。
- 退出登录清理在线会话与内存中模型密钥副本、暂停学校请求，但不删除本地学习数据或用户主动保存的模型凭据。删除凭据有独立操作。

### 4.2 材料、笔记与来源

- 无模型配置时，允许学校同步、阅读原文、查看截图和导出 PDF；分析/问答提示配置模型。
- 无文本时不伪造识别结果；仅截图不等于已具备可分析文本，不能显示已成功生成课堂笔记。
- ASR 超过 45 秒空白、未归类片段和部分整理状态可见；覆盖率不得称为识别准确率。
- 分析保留使用的完整 evidence 快照与材料摘要值；刷新材料不改变旧笔记引用所指原话。
- 截止时间必须有直接原文证据，不推算；作业始终可见“待核验”属性。未提取到不意味着老师没有布置。
- 无效 JSON/结构/引用失败执行有限重试；鉴权、限额、网络错误展示可理解原因，不陷入无限自动重试。
- 对整次分析失败，不发布不完整的新结果；已验证的时间轴部分整理状态可保存并显示，但必须与失败区分。
- 阅读记忆至少包含账号、课次、标签、搜索词、锚点/滚动位置；材料变化导致锚点无效时安全回到可用位置。旧版 localStorage 不承诺自动迁移。
- 截图索引离线可读不代表图片已下载。已缓存图片离线显示；未缓存图片显示可重试的离线状态，不承诺自动离线保存全部图片。

### 4.3 问答、作业与模型

- 问答范围可为整门课程或指定课次；空材料不调用模型，无有效来源不展示伪造引用。
- 既有聊天按账号/课程保存；点击来源可打开相应课次及引用文本，旧引用不被新材料静默替换。
- 相同作业在重分析后保留完成状态；移除/改写的作业标记被替代，不继续作为当前待办展示。不自动合并跨课次的同一作业。
- 模型配置按账号隔离；服务地址更换不携带旧地址的 Key；支持保留、替换和移除 Key，界面及日志不回显完整值。
- 保持 DeepSeek 官方地址当前 Responses/结构化输出行为、其他服务兼容 Chat Completions 行为，以及 localhost HTTP 无 Key 模型。具体行为以当前 `learning.py` 和合成响应测试为准，不在迁移时切换接口。
- 分析/问答前可见“发送课堂文本到所配置服务，可能产生费用”；截图不发送给模型。

### 4.4 任务与恢复

- 覆盖同步课程、同步课表、同步课次、获取材料、分析、PDF 导出和课程自动化任务。问答可作为独立交互请求，但同样受账号、超时及关闭生命周期管理。
- 状态包含排队、运行、完成、失败、需登录、中断；同一账号/任务类型/目标合并重复入队。
- 重启将未完成旧任务标记为中断，不在未知会话下自动重放。重试创建可追踪的新执行，已完成数据保持幂等。
- 学校和模型请求有超时；关闭程序不等待无上限网络请求。当前 C ABI 未证明支持即时取消，M0 须实现可控超时与安全释放，并明确用户可观察的停止边界。
- 顶部、任务页、阅读器使用同一任务源；UI 不显示虚构百分比。以阶段进度表达无法精确计量的网络等待。

### 4.5 课程自动化

- 列表支持搜索、全选/全不选、仅显示已开启；批量操作只影响当前筛选结果。
- 修改只改变草稿，统一保存后生效。保存过程中防重复提交；离开有未保存修改的页面时允许保存、放弃或留在当前页。
- 推荐一次保存同账号全部变更到单个事务；失败保留全部草稿并维持旧生效规则。不得像旧多请求实现一样在局部成功后仍含糊显示全部保存失败。
- 未启用自动获取时自动笔记禁用；关闭自动获取同时关闭自动笔记。运行中的规则被修改或暂停后，旧任务不能覆盖新配置。
- 时间按北京时间计算，与用户 Windows 时区无关：真实课表中每次上课的次日 00:00 起检查，未完成每两小时重试。
- 首次开启只从昨天及之后课次建立追踪，不批量分析更早历史；历史课次可手动处理。
- 每日同步过去 7 天至未来 21 天的真实课表；无课表则等待，不推算每周重复课程；滚动课表更新不得丢失已有待检查项。
- 无回放、空材料、登录过期、模型失败均保持待检查；先持久化下次检查时间再发请求，避免失败导致快速重试。
- 材料及所需分析成功后停止追踪该课次；重复 tick、休眠恢复和重启不得对已完成课次重复分析计费。
- 应用打开且会话有效时执行；睡眠期间不执行，唤醒后合并检查到期项，不按错过的 tick 数量重复补跑。

### 4.6 导出

- Markdown 包含课程/课次、时间轴、来源、相关提取信息及原文；缺失字段不伪造，中文和文件名可正常保存。
- PDF 保留首次出现顺序，合并非相邻重复页面，保守保留文字、批注和颜色变化。不得降低原始分辨率或使用有损再编码替代无损嵌入。
- 对齐当前限制：最多 1000 张、并行下载不超过 4 张、单图 12 MiB、单图 2000 万像素、累计下载和解码数据预算按现有导出器分别执行 256 MiB 上限。
- 图片下载只允许既有学校资源域和受支持图像格式，不转发学校/模型凭据，不跟随重定向。
- 通过临时文件生成、校验后替换；失败不覆盖上次完整 PDF。材料快照变化后提示旧导出已过期，允许重新生成。
- 打开/保存文件使用系统对话框和安全文件名；路径含中文、空格、保留字符和目标被占用时有明确处理。

## 5. 存储与旧版迁移

新数据位于系统 API 返回的当前用户 LocalAppData 下 `BUAA Learn Native`，不得依赖启动目录或写入安装目录。子目录区分数据库、导出、缓存、日志与迁移备份。Windows ACL 限制其他普通账号访问；不使用 `chmod` 作为 Windows 保护措施。

持久化对象至少覆盖 course、lesson、materials、analysis、task、chat、automation、job、semester/schedule 元信息、模型非敏感配置和阅读记忆。Rust Store 统一管理学习数据，新增类型或 schema 先定义版本与向前升级规则，不另建未说明的第二套业务数据库。

迁移要求：

1. 用户选择旧数据位置，程序识别格式、账号分区和源/目标是否同文件。以学校账号确认映射，旧 owner 为 SHA-256 前 24 位，新 owner 为学校账号；不猜测其他账号归属。
2. 独占迁移操作，暂停目标调度和写任务；检测旧程序写入并要求关闭。使用 SQLite backup API 创建包含 WAL 数据的一致性备份，并检查完整性。
3. 只读预检，显示各对象新增、相同、冲突、无法支持的数量，以及 PDF 情况；明确缺失本地图片和阅读位置不会凭空恢复。
4. 相同内容跳过；课程/课次/元信息可按明确定义规则只补缺字段并保留目标值；笔记、材料、任务等内容冲突默认阻止整次写入，保留源和目标，输出本地冲突报告。首版不做静默覆盖。
5. 所有目标业务记录在一个事务内导入；PDF 先复制并校验到暂存目录，再按映射登记。文件与数据库不能共用事务，必须设计迁移清单与失败恢复流程，不能声称跨两者原子提交。
6. 导入的自动化全部禁用，保留原设置供用户核对后重新开启；导入任务历史不恢复执行，旧排队/运行状态改为中断并保留原状态记录。
7. 配置只导入非敏感值；不从旧配置复制学校会话或模型 Key，提示重新填写。旧 PDF 路径须重映射到原生账号目录并检查材料摘要匹配。
8. 导入完成展示数量、冲突和备份位置。相同数据再次导入不产生重复；失败恢复目标并清理暂存，源文件保持原样。

现有迁移脚本只能作为逻辑参考，特别是 `fcntl` 锁、POSIX 权限与导出只备份不归位的行为都需要补齐。
